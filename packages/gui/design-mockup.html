Explaining lifetimes.md✕
longest-str.rs✕
markdown · 2026-07-12

A lifetime is the span during which a reference is valid. Rust tracks it at compile time so a reference can never outlive what it points to — no dangling pointers, no GC needed.

Why we need them

Consider a function returning the longer of two string slices:

fn longest(x: &str, y: &str) -> &str {
    if x.len() > y.len() { x } else { y }
}

The compiler can’t tell which input the returned reference is tied to, so it refuses to compile. Lifetime parameters make that relationship explicit.

The elision rules

  1. Each reference input gets its own lifetime.
  2. Exactly one input lifetime → all outputs share it.
  3. Many inputs, but one is &self → outputs take self’s lifetime.
One lifetime 'a says: the result lives at most as long as the shorter of the two inputs.
