## Why

The right panel of the desktop app needs a real agent — an opencode-style autonomous coding agent that holds stateful multi-turn conversations, persists session history, exposes slash commands (`/new`, `/sessions`, `/compact`, …), runs filesystem/shell tools inside the working folder, and renders the live transcript with notebook-margin tool-call cards. The current stack hand-rolls all of this in Rust on top of `rig-core 0.39` (`packages/learn-agent` crate: `agent.rs`, `tools/*`, `model.rs`, `state.rs`, `render.rs`, `workflow.rs`, `utils.rs`, `prompts/`, `mock/` — ~3,300 lines across 16 files). Maintaining a hand-rolled agent loop, multi-provider dispatch, streaming glue, JSONL session storage, and tool implementations is a long-term maintenance burden that grows with every feature added.

The [pi](https://github.com/earendil-works/pi) framework (`@earendil-works/pi-coding-agent`, `@earendil-works/pi-ai`) already provides all of this natively: an `agentLoop` with automatic tool execution and validation, `createAgentSession` + `AgentSessionRuntime` with `newSession`/`switchSession`/`fork`, `SessionManager` with JSONL tree persistence under `~/.pi/agent/sessions/<cwd>/`, `pi.registerCommand` for slash commands (`/new`, `/sessions`, `/compact`, `/clear`, `/help`, …), built-in `read`/`write`/`edit`/`bash`/`grep`/`find`/`ls` tools, `AbortSignal` cancellation, BYOK via `AuthStorage.setRuntimeApiKey` (key never persisted), and custom provider registration via `pi.registerProvider` (handles `base_url` overrides for OpenRouter/self-hosted endpoints). Adopting pi lets us delete the entire Rust agent surface and never re-implement sessions/commands/tool loops again.

## What Changes

- **BREAKING**: Delete the entire `packages/learn-agent/` Rust crate (workspace member removal, workspace dep removal). All agent logic moves off the Rust backend.
- **BREAKING**: Delete the Tauri commands that depend on `learn-agent`: `chat_create_topic` (agent session/topic creation via `learn_topic`) and `test_key` (pre-save API key verification via `LocalModelClient::stream`). The `agent:done` / `agent:error` Tauri events are removed with `chat_create_topic`.
- Remove `packages/gui/src-tauri/src/agent.rs` and `packages/gui/src-tauri/src/commands.rs` entirely.
- Inline the `Provider` enum (previously `learn_agent::model::Provider`) into `packages/gui/src-tauri/src/config.rs` so non-secret app config (`provider`, `model`, `base_url`, `last_working_folder`) keeps round-tripping through app-data without an inter-crate dependency.
- Aggressively prune Rust dependencies in `packages/gui/src-tauri/Cargo.toml`: drop `futures`, drop the `tokio` "time" feature (only `test_key` needed `tokio::time::timeout`), and remove `learn-agent.workspace = true`.
- Delete `packages/gui/src/components/ChatDialog.vue` (frontend only ever invoked the removed `chat_create_topic`).
- Remove `TopicCreated`, `chatCreateTopic`, `TestKeyParams`, `testKey` exports from `packages/gui/src/lib/commands.ts` and scrub any callers in composables/components.
- Introduce a Node **pi sidecar**: a TypeScript program (`packages/gui/sidecar/`) that the Tauri Rust backend launches as a child process via Tauri's `externalBin`/sidecar mechanism. The sidecar imports `@earendil-works/pi-coding-agent`, receives BYOK config (API key + provider + `base_url` + model + `cwd` + session id) over **stdin** as JSON (never argv — prevents `ps` key leakage), injects the key into `AuthStorage.setRuntimeApiKey` (never persisted to disk), drives a pi `createAgentSession`, and emits `AgentEvent` events over **stdout** as JSONL.
- Register opencode-style slash commands via `pi.registerCommand` in the sidecar: `/new` (`runtime.newSession()`), `/sessions` (`SessionManager.list` + emit a `ui_select` request back to the frontend over stdin), `/compact`, `/clear`, `/help`, `/model` (`cycleModel`/`setModel`).
- Use pi's built-in toolset (`read`/`write`/`edit`/`bash`/`grep`/`find`/`ls`) — no custom Rust `Tool` implementations. The existing strict `Workspace` canonicalize-then-prefix path-escape guard is NOT carried over in v1; pi's tools operate on the process `cwd` (= working folder) which bounds the blast radius without the bespoke security layer.
- Add a new Tauri command surface in `packages/gui/src-tauri/src/` that proxies to the sidecar: `agent_new_session`, `agent_send`, `agent_cancel`, `agent_list_sessions`, `agent_load_session`. These commands own the sidecar subprocess lifecycle, forward stdin/stdout JSONL, and emit a single `agent:event` Tauri event carrying `{ session_id, event }` — preserving the `AgentEvent` discriminated-union contract `TextDelta`/`ToolCall`/`ToolResult`/`Done`/`Error` that the frontend already expects from the retired `right-agent-panel-rig-tools` spec.
- Frontend: introduce `AgentChat.vue` (opencode-style right panel), `SlashMenu.vue` (popover triggered by a leading `/`), `ToolCallCard.vue` (notebook-margin card with vermilion `--color-accent` 2px left border, pulsing indicator while running, `--color-mastered` ok / `--color-brand-1` error, `<details>` expandable to args JSON + result), `SessionsPanel.vue` (inline overlay with `← back` + title search; row metadata simplified to `<n> msgs · <Xh ago>`), `useAgentSession` composable (owns `sessionId`, `messages`, `busy`, `pendingConfirm`, `sessionsOpen`, `sessions`, `sessionsQuery`; subscribes to `agent:event` filtered by `session_id`), `lib/slash-commands.ts` (pure registry + `matchInput`), and `lib/time.ts` (`relativeTime`).
- OpenSpec cleanup: delete the two superseded in-progress changes — `openspec/changes/gui-agent-capability-spike/` (Phase 1 rig capability spike, all tasks completed; its design is now obsolete) and `openspec/changes/right-agent-panel-rig-tools/` (the rig-based agent panel plan, only Tasks 1–2 done; fully superseded). Migrate the frontend-facing spec (`agent-chat-ui`) and the Tauri command contract (`agent-tauri-commands`) into this change, adapted to drop "replace `chat_create_topic`" wording (already removed in the code-deletion commit) and to parameterize "rig"/`LocalModelClient`/`CancellationToken` implementation details behind the new `agent-pi-sidecar` capability.

## Capabilities

### New Capabilities

- `agent-chat-ui`: the right-panel Vue UI — `AgentChat.vue` header + streaming transcript + send/stop row, stateless `SlashMenu.vue` popover (leading-`/` triggered, keyboard-navigable, fade-in 80 ms), notebook-margin `ToolCallCard.vue` (running/ok/error states with `<details>` expansion), inline `/new` confirm chip, `/sessions` inline overlay `SessionsPanel.vue` with title-substring search and `← back` restore, Send/Stop control toggling, empty-state prompt "Type `/` for commands, or just ask." Composable-driven (`useAgentSession`) with no per-component event wiring. Row metadata: `<n> msgs · <Xh ago>` (simplified — no tool-call count).
- `agent-tauri-commands`: the Tauri command surface owned by the Rust backend — `agent_new_session`, `agent_send`, `agent_cancel`, `agent_list_sessions`, `agent_load_session`. Each is a thin proxy that spawns/forwards to the pi Node sidecar (see `agent-pi-sidecar`). Emits a single `agent:event` Tauri event carrying `{ session_id, event: AgentEvent }` where `AgentEvent` is the five-variant discriminated union (`TextDelta { delta }`, `ToolCall { id, name, args }`, `ToolResult { id, name, status, result }`, `Done`, `Error { message }`). The command contract is backend-agnostic; the pi sidecar realizes it.
- `agent-pi-sidecar`: the Node child-process agent backend — launched by Tauri's sidecar mechanism, receives BYOK config (including the API key) over stdin as JSON (never argv), injects the key into `AuthStorage.setRuntimeApiKey` (never persisted), drives `createAgentSession` + `AgentSessionRuntime`, adapts pi's `AgentSessionEvent` stream into the five-variant `AgentEvent` JSONL on stdout, registers slash commands (`/new`, `/sessions`, `/compact`, `/clear`, `/help`, `/model`) via `pi.registerCommand`, forwards user-facing UI requests (e.g. `/sessions` picker) back to the frontend via a `ui_request` event channel, and uses pi's built-in `read`/`write`/`edit`/`bash`/`grep`/`find`/`ls` tools scoped to the working-folder `cwd`.

## Impact

- **Rust crates**:
  - `packages/learn-agent/` — entire crate deleted. Workspace `members` loses the entry; `workspace.dependencies` loses `learn-agent = { path = "packages/learn-agent" }`.
  - `packages/gui/src-tauri/` — `src/agent.rs` deleted (was `chat_create_topic`); `src/commands.rs` deleted (was `test_key`); `src/lib.rs` drops `mod agent;` / `mod commands;` and the `chat_create_topic` + `test_key` invoke-handler registrations; `src/config.rs` gains an inlined `Provider` enum (same `#[serde(rename_all="lowercase")]` shape, `#[default] OpenAi`); `Cargo.toml` drops `learn-agent.workspace = true`, `futures.workspace = true`, and the `tokio` "time" feature. `src/keychain.rs` and `src/project.rs` are unchanged (OS keychain and folder-pick + v1-topic scan are independent of the agent backend). A new `src/sidecar.rs` (or equivalent) owns the Node child-process lifecycle and stdin/stdout JSONL forwarding.
- **Frontend (`packages/gui/src/`)**:
  - new: `components/AgentChat.vue`, `components/SlashMenu.vue`, `components/ToolCallCard.vue`, `components/SessionsPanel.vue`, `composables/useAgentSession.ts`, `lib/slash-commands.ts`, `lib/time.ts`.
  - modified: `lib/commands.ts` (remove `TopicCreated`/`chatCreateTopic`/`TestKeyParams`/`testKey`; add `AgentEvent`/`ChatBlock`/`ChatMessage`/`SessionMeta`/`ChatRow` discriminated union types + the five `agent_*` command wrappers), `lib/ui.ts` (`slashPill`, `toolCard` class strings), `components/TopicList.vue` (drop the `ChatDialog` import and rendering; the new panel mounts at the App level instead), `composables/useSetupForm.ts` / `components/SetupScreen.vue` (drop the pre-save `testKey` verification; the form just persists key + config — verification moves to the sidecar's session boot). `App.vue` renders `AgentChat.vue` in the right-panel slot with the working-folder id from config.
  - removed: `components/ChatDialog.vue`.
- **Sidecar (`packages/gui/sidecar/`)**: new TypeScript package depending on `@earendil-works/pi-coding-agent`, `@earendil-works/pi-ai`, `typebox`, `zod`. Bundled via `pnpm build` into a single Node-runnable entry that Tauri's `externalBin` targets.
- **Tauri events**: `agent:done` / `agent:error` removed; new `agent:event` carrying `{ session_id, event: AgentEvent }`.
- **Filesystem layout**: the planned-but-never-built `<working_folder>/.learn/sessions/<id>.jsonl` is NOT introduced. pi's own `SessionManager` persists sessions under `~/.pi/agent/sessions/<cwd>/` (JSONL tree with `id`/`parentId` for in-place branching). The frontend never touches session files directly; `agent_list_sessions` reads via the sidecar.
- **Tauri build config** (`tauri.conf.json`): `externalBin` gains the sidecar entry; `pnpm build` must build the sidecar before Tauri bundles so the binary is on disk at bundle time.
- **App distribution size**: +40-70 MB per platform from bundling a Node runtime plus npm deps (`pi-ai`, `pi-coding-agent`, `typebox`, `zod`). Tauri's system WebView (macOS WebKit / Windows WebView2 / Linux WebKitGTK) is NOT bundled — a hard win over an Electron migration (~200-300 MB with Chromium). Net app size stays well under Electron-equivalent.
- **Tests**: `learn-agent` unit tests are deleted with the crate. Sidecar gains unit tests for the `AgentSessionEvent` → `AgentEvent` mapping and slash-command registry. `useAgentSession` gains vitest coverage of `slash-commands.matchInput` and `relativeTime`. End-to-end manual smoke covers `/new`, a real prompt that invokes `write` + `bash`, the Stop button, app-restart session restore via `/sessions`.
- **OpenSpec**: the two superseded changes (`openspec/changes/gui-agent-capability-spike/`, `openspec/changes/right-agent-panel-rig-tools/`) are deleted alongside this proposal landing. Their salient frontend (`agent-chat-ui`) and command-contract (`agent-tauri-commands`) specs are migrated (adapted) into this change; the Rust-specific `agent-tools` / `agent-session` / `agent-sessions-storage` / `agent-keychain`-test-key / `agent-learn-topic` / `agent-model-client` capability specs are dropped (their concerns are either obsolete or relocated into `agent-pi-sidecar`).
- **No new external services**: pi is a library, not a hosted service. BYOK semantics are unchanged — the user's API key still flows from the OS keychain through the Rust backend and is forwarded to the sidecar over stdin at session start; it is never written to disk by the sidecar (`AuthStorage.setRuntimeApiKey` is runtime-only).
